# Agent guidance for ZView GUI

## Purpose and sources of truth

ZView GUI is an experimental native and browser inspector for Zephyr RTOS.
It uses one Rust/GPUI UI; ZView supplies acquisition and recording decoding.
Read [README.md](README.md) for supported workflows,
[CONTRIBUTING.md](CONTRIBUTING.md) for delivery and release rules, and
[web-ui/README.md](web-ui/README.md) for the adapter contract and browser setup.
Use manifests, scripts and [.github/workflows/ci.yml](.github/workflows/ci.yml)
to confirm exact dependency pins and checks; do not duplicate changing versions here.

## Architecture and boundaries

- `src/lib.rs` owns application state, navigation and shared rendering.
  `src/*_detail.rs`, chart modules and `src/layout.rs` implement shared views.
  Keep native and WASM behavior coherent; respect target-specific `cfg` gates.
- `src/header.rs` owns shared header controls and geometry. `src/native_titlebar.rs`
  adds native window chrome and shutdown integration. Sidebar branding and
  Help/About actions are shared; do not recreate host-specific copies.
- `src/model.rs` parses decoded frames; `src/kernel_model.rs` defines kernel
  object semantics. `src/thread_sort.rs` orders visible thread rows.
  Keep rendering and keyboard navigation on the same ordering.
- `src/adapter_protocol.rs` defines the typed wire contract and pure client state.
  `src/web_adapter.rs` owns browser HTTP/WebSocket integration;
  `src/web_session.rs` renders the session controls/form and
  `src/session_settings.rs` contains testable settings/discovery value rules.
- `web-ui/zview_gui/` is the Python adapter: `server.py` exposes HTTP/WebSocket
  endpoints, `session.py` manages acquisition/replay, and the build, view-selection
  and heap-capture modules manage their respective contexts and ownership.
  Reuse ZView APIs; do not create another decoder or drive its TUI.
- `web/main.js` and `web/startup.mjs` initialize the shared WASM UI and connect
  it to the required adapter. There is no direct browser document loader.
  Do not move session state or build a second UI framework into JavaScript.
- Native and web share the same UI foundation and Python adapter for Live/Replay.
  Both hosts always require that adapter. `export_recording.py` regenerates
  recorded test fixtures using CI's pinned exporter backend; it is not a native
  application entry point. Do not infer sibling checkouts or inject unrelated
  source trees into Python's import path.
- `target/web` is generated by `scripts/web_ui.py`, not hand-maintained source.
  `hatch_build.py` embeds the built site into the Python wheel.

## Correctness and interaction rules

- Preserve unavailable readings as unavailable, not zero, empty queues or inactivity.
  Use object identities rather than row positions; names and addresses can be reused.
- Live discovery describes the session inventory, not just currently polled objects.
  Do not attribute connected-firmware capabilities to a different edited draft.
- Preserve manual session-field edits during background detection; explicit refresh
  may replace them on success. Collapsing Advanced must not change submitted values.
  Reject stale asynchronous responses after configuration/session changes.
- Preserve session IDs, event sequencing, stale-message checks and controlling-tab
  ownership. Navigation requests view-specific data; heap maps are on-demand and
  must release demand when leaving the relevant view.
- Charts show sampled observations, not complete execution events. Missing readings
  break history; percentage readings and count/state series have different interpolation
  semantics. Do not invent events or silently connect across observation gaps.
- History cache accounting is estimated chart storage for the current view, not total
  process memory. Screen changes reset it; preserve time/memory limits and warnings.
- Keep keyboard navigation, focus indication, accessible labels and non-color status
  cues. Screen info explanations support hover and keyboard focus without pointer
  click-to-pin behavior. Do not hide actionable errors only in tooltips.

## Setup and running

Run commands from the repository root. Native builds require Rust and GPUI's platform
prerequisites; headless Rust tests still depend on native GPUI libraries.

| Workflow | Command / reference |
| --- | --- |
| Native adapter-backed UI | `just gui` (requires the Python adapter environment) |
| Browser tool installation | `just web-setup` (installs nightly, WASM target and pinned wasm-bindgen) |
| Browser debug build | `python3 scripts/web_ui.py build` |
| Browser adapter-backed UI | `just web-gui --python .venv-web/bin/python` |
| Optimized browser site | `just web-build` |

For Python adapter development use the separate Python 3.12 environment and editable
installation in `web-ui/README.md`. The browser adapter and desktop exporter have
different backend requirements; do not reuse one environment assuming compatibility.
For optional browser smoke checks install `web-ui/requirements-browser.txt` in the
selected adapter environment and install Playwright's Chromium per CI.
Setup installs/downloads dependencies; do not run it silently for documentation work.

## Validation

Commands below are defined in project guides or CI, not a claim they ran on this machine.
Use the intended interpreter/environment; native and browser compilation are separate.

| Check | Command |
| --- | --- |
| Formatting | `cargo fmt --check` |
| Rust tests | `cargo test` |
| Focused Rust tests | `cargo test --lib <test-name-or-filter>` |
| Native lint | `cargo clippy --all-targets -- -D warnings` |
| WASM lint | `cargo +nightly clippy --locked --lib --target wasm32-unknown-unknown -- -D warnings` |
| Browser startup | `node --test web/startup.test.mjs` |
| Browser launcher | `python3 -m unittest discover -s scripts -p test_web_ui.py -v` |
| Python adapter | `python -m unittest discover -s web-ui -p 'test_*.py' -v` |
| Full browser smoke | `python web-ui/browser_smoke.py` (requires built site and browser dependencies) |
| Focused sidebar smoke | `python web-ui/browser_smoke.py --sidebar-only` |

CI additionally checks wheel construction/serving and recording fixture regeneration.
Opt-in native adapter integration checks require `ZVIEW_GUI_PYTHON` with this
checkout's adapter installed. Fixture regeneration uses CI's separate pinned
exporter environment; do not assume its backend pin matches the adapter.
The [official benchmark guide](test-data/zview-bench-60s/README.md) documents fixture
provenance and regeneration; retain recordings and their matching ELF artifacts.

## Live, Replay and workspace safety

- Replay decoding requires the recording's matching ELF or an appropriate build.
  Decoding progress is not original capture timing or hardware acquisition throughput.
- Live needs matching firmware already running and the correct probe/GDB connection.
  Connecting does not flash firmware. Ask before flashing, resetting hardware or
  operating external services; do not change another project's build/worktree.
- Build-directory Git metadata is checkout context, not proof of firmware provenance.
  Requested polling periods (including zero) do not guarantee achieved sample rates.
- Adapter file paths are server-local and constrained by `--data-root`; preserve path,
  symlink-escape and input-size checks. Use `--site` when testing this checkout's
  generated browser UI through an installed adapter instead of the packaged site.
- Preserve unrelated edits, fixtures, credentials and local configuration.
  Do not edit generated outputs. Ignored directories are not automatically disposable;
  preview exact cleanup paths and obtain approval before deleting them.

## Commits and pull requests

- Follow `CONTRIBUTING.md`: use feature branches, Conventional Commit subjects and PRs.
  Include meaningful bodies explaining purpose, behavior, validation and limitations.
- Before committing check `git var GIT_AUTHOR_IDENT`, `git var GIT_COMMITTER_IDENT`
  and configured remotes. Environment overrides can change effective Git identity.
  Confirm the intended author name and email with the user before creating commits
  or opening a PR; do not assume the machine's configured identity is appropriate.
  Ask before changing identity; never modify global Git settings for this project.
  Verify the destination is `zano-systems/zview-gui`, not an outdated similarly named
  repository or Delta's `local` backlink.
- Group coherent changes into reviewable commits. Report actual checks, failures,
  ignored/skipped tests, manual/platform coverage and remaining assumptions in the PR.
  Earlier green CI is not evidence for a later revision.
- Do not merge into `main`, rewrite published history, push release tags or publish
  packages without explicit authorization. Keep version files synchronized when an
  authorized release changes versions; do not bump versions for every UI change.
